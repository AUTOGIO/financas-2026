Problem Context

Online Bitcoin custody is a
governance liability.

Exchange-held or internet-connected wallets expose the company to threats that cannot be fully mitigated by software alone.

⛔ Online / Exchange Custody Risks
✗Exchange insolvency — assets frozen or lost (FTX, Celsius precedents)
✗API key or credential theft — funds transferred without physical access
✗Third-party custody — company does not legally control the private key
✗Transaction metadata exposed — counterparties identifiable
✗No board-level control over who can initiate a transfer
✅ What Cold Storage Solves
✓Private keys never touch the internet — offline by design
✓Company owns its keys — no third-party custodian dependency
✓Signing requires physical access to the offline device
✓Watch-only monitoring with zero spending capability on mobile
✓Governance controls define who can authorize a transaction
Solution Architecture — Three Components

One principle: sign offline, monitor online.

🖥

Electrum Wallet

Offline Windows Desktop

Holds the private key. Never connected to the internet. All transaction signing happens here. Physical access required.

🔴 Air-gapped · No internet access
📱

BlueWallet

Watch-Only iPhone

Views balances and transaction history only. Cannot spend or sign. Provides real-time monitoring without any custody risk.

🟢 Online · Zero signing authority
🎲

Ian Coleman BIP39

Offline Seed Generator

Open-source tool run offline to generate the wallet seed phrase. Never connected to internet during generation. Auditable code.

🟣 Offline · Open source · Auditable
Operational Workflow

Four-step process. Private key stays offline forever.

STEP 1 · ONCE
🎲
Seed Generation
Ian Coleman runs offline. Cryptographically secure 24-word seed created. Device never connects to internet.
→
STEP 2 · ONCE
🖥
Offline Wallet Setup
Electrum installed on air-gapped Windows PC. Seed imported. Wallet created. PC stays offline permanently.
→
STEP 3 · ONCE
📱
Watch-Only Setup
Public key (xpub only) exported to BlueWallet on iPhone. No private data leaves the offline PC.
→
ONGOING
✍️
Sign & Broadcast
Transaction built on iPhone, transferred via QR code to offline PC for signing, then returned for broadcast. Key never online.
🔴 Offline zone: Steps 1–2 · Signing device always air-gapped 🟢 Online zone: Steps 3–4 monitoring · Transaction broadcast only ⚡ QR code: only bridge between zones · No network connection
Security Benefits

Designed to reduce exposure, not eliminate all risk.

🛡
Private Key Isolation
The signing key exists only on an offline device. Remote attackers have no viable attack vector — there is no network to traverse.
✓
📡
Zero Internet Exposure for Signing
Transaction signatures are created offline and moved via QR code only — eliminating the most common attack vector for crypto theft.
✓
👁
Mobile Monitoring Without Spending Risk
BlueWallet on iPhone uses a watch-only configuration — it can see balances and history but is cryptographically incapable of moving funds.
✓
🔢
Auditable Seed Generation
Ian Coleman is open-source code that can be independently audited. Running offline means the seed was never transmitted — provably.
✓
🏛
Custody Discipline & Fiduciary Clarity
The company — not a third-party custodian — controls the asset. Directors can define and enforce who has access and under what conditions.
✓
Governance Framework

Controls the board must define and approve.

🔑
Access Control
  • Named authorized signers only (minimum 2)
  • Physical key + PIN required for device
  • Dual-authorization for transactions above threshold
  • Access log maintained and reviewed quarterly
💾
Seed Backup & Recovery
  • Seed phrase stored in physical vault (not digital)
  • Minimum 2 geographically separate copies
  • Recovery test conducted annually
  • Board officer holds one sealed copy
✅
Transaction Approval
  • Written authorization required before any signing
  • CEO + CFO sign-off for amounts above threshold
  • Board resolution required for >25% of holdings
  • All transactions documented with business purpose
📊
Audit Trail
  • Blockchain provides immutable public record
  • BlueWallet monitoring exported monthly
  • Internal log of all access events
  • Annual third-party security review
🚨
Emergency Recovery
  • Pre-defined protocol for device loss/failure
  • Secondary authorized signer on standby
  • Legal instruction in company records
  • Board notified within 24h of any incident
📅
Periodic Review
  • Quarterly board update on holdings status
  • Annual policy and procedure review
  • Hardware integrity check every 6 months
  • Custody policy updated for regulatory changes

Interactive Board Exercise — Governance Decision

Scenario: Urgent Treasury Event

The situation: The CFO receives notice that a strategic acquisition requires immediate Bitcoin transfer representing 40% of holdings within 24 hours. The primary authorized signer is traveling internationally and unreachable. What should the board direct?

⚡
Option A
Proceed Immediately
Bypass dual-authorization. Primary signer approves by phone. Move funds to close the deal.
⏸
Option B
Wait for Authorization
Delay transfer until the primary signer returns and full authorization is obtained.
📋
Option C
Activate Emergency Protocol
Invoke the pre-approved emergency procedure: secondary signer, full documentation, board notification.
⚠️ Option A creates serious governance risk. Phone authorization is not verifiable and bypasses written controls. If anything goes wrong, fiduciary responsibility is exposed. This action would invalidate your security policy and set a precedent for bypassing controls under pressure.
⚠️ Option B maintains governance integrity but may cost the deal. While this demonstrates discipline, the better answer is to have a pre-defined emergency path so urgency never forces a governance breach. This scenario reveals a gap in the current framework.
✅ Option C is correct governance. A pre-defined emergency protocol with a secondary authorized signer, documented procedure, and immediate board notification allows decisive action without compromising controls. This is why the board must approve an emergency protocol as part of this initiative.
